# 金融系统 · 数学近似建模与可行性评估

> 方法：先从 `src/engine.js` 抽出**精确递推式**，再推导近似解析式，
> 最后用模拟器（`tools/fin-model.mjs`，300 局）**逐条校准**。
> 校准不上的地方就是模型错的地方 —— 这类偏差本身就是结论。

---

## 一、模型

### 1.1 地价与地产指数（REI）

```
landPrice(t) = floor100(basePrice × R / 100)          R = REI
assetValue(t) = landPrice(t) × levelValue[level]      levelValue = [0, 1.0, 1.65, 2.45, 3.45, 4.7]
```

REI 的季度更新（每季度一次）：

```
R_{n+1} = R_n + ρ·(F_n − R_n) + η_n            ρ = 0.06（回归速度）
                                               η ~ U(−8, +8)（季末抖动）
         + 活跃度项（买地 +0.5/次、升级 +0.8/次、赎回 +1.0、抵押 −1.5、破产 −5 …）

F_n = 100 + 35·(已持有地块 / 22) + A·sin(2πn/T + φ)     ← "合理值"
A ∈ [0.7, 1.35]×46（每轮重抽）,  T ∈ [16, 30]
```

另有每名玩家回合的抖动 `reiTurnNoise = 2.2`（U 分布）。

### 1.2 股价

```
每季度：1 次大 tick（endTurn→quarterEnd）
       4 次小 tick（每个玩家回合结束，k = 0.25）

ret = drift·k + vol·k'·Z + 0.06_full·(1 − S/base) + 0.25_full·(R − 100)/100
      └ 漂移    └ 随机  └ 均值回归           └ 地产指数联动
      k = 1(大) / 0.25(小)，  k' = 1(大) / 0.45(小)
S ← max(1, S·(1 + ret))
```

### 1.3 抵押与追缴

```
抵押：L = LTV × V₀ = 0.60 × V₀
追缴：V_n < ratio × L = 1.10 × 0.60 × V₀ = 0.660 × V₀
```

### 1.4 物业税与租金

```
物业税/季 = assetValue × 0.012          （抵押中 ×0.5）
租金/次   = landPrice × rentRate[level] × (垄断 ? 1.5 : 1)
rentRate = [0, 0.24, 0.66, 1.24, 2.10, 3.50]
```

## 二、关键推导

### 2.1 REI 的方差与周期衰减

REI 是个 AR(1)（自回归系数 `1−ρ = 0.94`），它跟踪正弦目标时相当于一个**低通滤波器**：

```
角频率   ω = 2π/T ≈ 2π/23 = 0.273
单频增益 g = 1/√(1 + (ω/ρ)²) = 1/√(1 + (0.273/0.06)²) = 0.215
```

| 项 | 预测 SD |
|---|---|
| 噪声项 √(σ²/3 / (1−(1−ρ)²)) | 13.5 |
| 周期项（**未衰减**） A/√2 | 33.3 |
| 周期项（**按单频增益衰减**） A·g/√2 | 7.2 |
| 合计 | **15.3** |

**实测 17.5** ✓ 总方差吻合（差 13%）。

#### ⚠️ 但"周期被砍到 21%"这个结论是错的 —— 实测反证

`cycleWave()` **每 T 个季度会重抽周期长度和相位**，所以它不是一个单一频率的正弦，
而是一个**分段正弦**（低频能量远多于单频假设）。实测扫描（`tools/fin-model.mjs` 同源方法）：

| `reiCycleAmp` | 实测振幅 | 相对基线 | 边际增益 |
|---|---|---|---|
| 46（现值） | 61.3 | 1.00 | — |
| 92 | 78.1 | 1.27 | 0.37 |
| 150 | 95.7 | 1.56 | 0.30 |
| 250 | 143.4 | 2.34 | 0.48 |
| 400 | 209.7 | 3.42 | 0.44 |

标称振幅放大 **8.7 倍** → 实测振幅只放大 **3.42 倍**。

**⇒ 有效增益 ≈ 0.42，不是推导的 0.215（差 2 倍）。**

拟合 `振幅 = √((c·A)² + n²)` 得 **c ≈ 0.50、噪声底 n ≈ 57**：

```
振幅(A) ≈ √((0.50·A)² + 57²)
```

**修正后的结论**（定性成立、定量打对折）：

- 周期确实被显著衰减：**振幅翻倍只换来实测振幅 +42%**
- 而且有一个 **约 57 点的噪声底**：A 从 46 提到 92，实测振幅只从 61 涨到 78（+27%）
- **"调大 `reiCycleAmp` 就能做出崩盘"这条路比看起来贵得多** ——
  想让实测振幅翻倍，得把 `reiCycleAmp` 从 46 提到约 **250**（5.4 倍）

> 这个偏差是**"建模后必须校准"**的最好例子：单频低通模型方向对、数值错一倍。
> 照 0.215 去做设计，会严重低估"做出崩盘"的成本。

### 2.2 追缴阈值（精确解，无拟合）

```
V_n / V₀ < ratio × LTV  =  1.10 × 0.60  =  0.660
```

**⇒ 地价必须从抵押时跌掉 34%，才会触发追缴。**

代入周期范围 `R ∈ [53, 147]`：

- 抵押时 **R > 80** → 后续低谷可能跌破 0.66R → **会被追缴**（这是绝大多数情况，所以"触发器很松"）
- 抵押时 **R < 80** → 低谷也追不上 → **永远不会被追缴**

但"被追缴"≠"被强制收地"：玩家有一个回合的赎回窗口，而 AI 会主动赎回。
所以实测是 **追缴 1.0 次/局、强制收地 0.5 次/局** —— 触发器松、但逃生通道也宽。

### 2.3 收租 ÷ 物业税

每季度 4 次落点、40 格 ⇒ 某块地每季度被踩 `4/40 = 0.1` 次，其中 1 次是地主自己：

```
收租事件期望 = 3/40 = 0.075 次/季度/块

比值 = 0.075 × rentRate[L] × mono / (levelValue[L] × 0.012)
```

| 等级 | 预测（无垄断） | 预测（垄断 ×1.5） |
|---|---|---|
| L1 | 1.50 | 2.25 |
| L3 | 3.16 | 4.74 |
| **L5** | **4.65** | **6.98** |

**实测全库 3.79** ✓ 量级吻合（实测偏低是因为前期等级低、REI 低）。

### 2.4 股价波动（模型高估 30%）

```
预测：SD_季度 = vol × √(1 + 4×0.45²) = vol × 1.345
```

| 代码 | vol | 预测 SD | 实测 SD | 比值 |
|---|---|---|---|---|
| 002 | 0.045 | 0.0605 | 0.0491 | 0.81 |
| 003 | 0.080 | 0.1076 | **0.0657** | **0.61** |
| 004 | 0.030 | 0.0403 | 0.0414 | 1.03 |
| 005 | 0.030 | 0.0403 | 0.0408 | 1.01 |
| 006 | 0.050 | 0.0673 | 0.0480 | 0.71 |

**模型系统性高估**，vol 越大偏得越多。原因：
1. **均值回归项** `0.06(1 − S/base)` 在高波动股上抽走更多方差
2. **极端值封顶**（黑天鹅 −15%、强势反弹）截断了尾部
3. 我忽略了 ret 的**乘法复合**（是 S·(1+ret) 不是对数收益）

**修正后的经验式**：`SD_季度 ≈ vol × 0.9`（vol ≤ 0.05 时），`≈ vol × 0.8`（vol = 0.08）。

## 三、升级方向的可行性评估

### ① 股价反映地租收入 —— **可行性：中（必须改设计）**

模型给出的关键数字：

```
每个地区约 2.8 块地 → 每季度期望收租 0.206 次
若按泊松计：SD = √0.206 = 0.454
变异系数 = 1/√λ = 220%
```

**⇒ 单季度的"全区地租收入"里有 220% 是纯噪声。**

**直接拿当季收入驱动股价 = 往股价里灌噪声，不是灌信息。** 会得到"看起来有基本面、实际是随机"的假联动，比现在更糟。

**可行的改法（按推荐度）**：

| 方案 | 说明 | 可行性 |
|---|---|---|
| **改用"该区已开发等级和"** | 慢变量，每季度变化小，天然平滑；且它**真的**反映该区被开发程度 | 🟢 高 |
| 用 EMA(8 季度) 平滑地租 | 把 220% 噪声压到 ~75% | 🟡 中 |
| 用累计地租（开盘至今） | 单调，但会退化成"谁先买谁永远涨" | 🟡 中 |

**我的结论**：**改成"按大区开发等级驱动对应行业股"**，不要用当季收入。

---

### ② 利率随周期波动 —— **可行性：高（模型给出精确旋钮）**

追缴阈值就是 `ratio × LTV`，所以只要让 `LTV` 随周期变，阈值就跟着变：

| 周期位置 | LTV | 追缴阈值 | 需要的跌幅 | 效果 |
|---|---|---|---|---|
| **繁荣** | 0.70 | 0.77 | **跌 23%** | 借钱多，但一跌就爆 |
| 现在 | 0.60 | 0.66 | 跌 34% | — |
| **衰退** | 0.45 | 0.50 | **跌 50%** | 借不到钱，但很难爆 |

配合 REI 实测 SD ≈ 17.5：
- **跌 23% ≈ 1.3σ** → 会发生，但不算频繁
- **跌 50% ≈ 2.9σ** → 罕见

**⇒ 这个杠杆很强、而且是可预测的**。模型能直接估出追缴次数的变化幅度，不用瞎调。

**代价**：需要把 `mortgageLtv` 从常数变成函数，且**存量贷款不受影响**（LTV 只影响新抵押）。改动约 15 行。

---

### ③ 信用评级影响融资成本 —— **可行性：高**

模型给出的自然函数形式：

```
负债率 d = 总贷款 / 总资产
LTV_p    = LTV_base × (1.2 − 0.6·clamp(d, 0, 1))      财务越健康借得越多
利息_p   = 0.06 + 0.14·clamp(d, 0, 1)                  杠杆越高越贵
```

配合已有的追缴阈值 `ratio × LTV`，**评级会自动传导到爆仓风险**上 —— 不需要新机制，只是给现有机制加一个玩家状态层。

**代价**：约 30 行 + UI 显示。**风险低**。

---

### ④ 做空 —— **可行性：低（模型劝退）**

用模型算一下做空的收益/风险比：

```
股价季度 SD ≈ vol × 0.9。取 vol = 0.05 → 4.5%/季度
持有 5 个季度：SD ≈ 4.5% × √5 ≈ 10%
```

也就是说**做空的盈亏在 5 个季度内基本由噪声主导（±10%）**。

更糟的是**可被操纵**：股价有一部分由玩家交易推动，一个资金充裕的玩家可以
**先做空、再砸盘、再买回**。现有的"滑点 + 双向 1% 手续费"只堵住了同回合往返，
**堵不住跨回合的做空打压**。

要做的话必须配一整套：借券费 + 借券上限 + 独立的强平线 + AI 也会做空 + 反操纵检测。
**成本远超收益**。

## 四、周期专项调查（第二轮，含实测 A/B）

> 第一轮我给的结论是"周期被 AR(1) 低通衰减"。第二轮做了更细的分解后，
> **这个归因不完整，而且修法建议是错的**。下面是修正后的版本。

### 4.1 先做分解：ΔREI 到底是什么构成的

把 `updateRei()` 的 ΔREI 拆成三项，跑 4197 个季度：

```
平均每季度 ΔREI = +1.35
   ├─ 回归项（向 fairRei 靠拢）   +0.33
   ├─ 活动项（买地/升级/赎回…）    +1.08   ← 占确定性漂移的 77%
   └─ 噪声项                     −0.06   （均值≈0 ✓）

确定性漂移解释了总变化的 104%
```

**活动项是系统性正漂移，不是噪声**（我第一轮把它归进了噪声，错了）。

来源自这条公式：`买地×0.5 + 升级×0.8 + 赎回×1.0 − 抵押×1.5 − 破产×5 − 卖地×1.5`。
实测每季度 **买地 0.78 次、升级 1.89 次、赎回 0.14 次、抵押 0.49 次** →
`0.78×0.5 + 1.89×0.8 + 0.14×1.0 − 0.49×1.5 = +1.31` ✓ 吻合。

**为什么天生偏正**：正项（买地、升级）是每个玩家一直在做的事，
负项（抵押、破产）很少发生。所以"正常打牌"就会把 REI 单向上推。

### 4.2 但去中心化救不了周期（实测负收益）

我实现了 `reiActivityBaseline`（每季度从 ΔREI 扣掉 1.3，让活动项在常规对局里均值为 0），
配对 A/B（4 种子 × 150 局）：

| 指标 | 基线 0（旧） | 去中心化 1.3 | 差值 |
|---|---|---|---|
| **总分** | 0.9359 | **0.9273** | **−0.0086** ❌ |
| 期末指数 | 128.5 | **116.25** | −12.25 ✓ |
| 追缴次数 | 0.49 | 1.15 | +0.66 |

**为什么没用**：因为有均值回归，**REI 的稳态由 `fairRei` 决定，而不是由累积漂移决定**。
而 `fairRei = 100 + 35×(已持有/22) + 周期波` —— 那个 **+35 的稀缺加成同样单调上升**，
地买光后 fair 就顶到 135，REI 自然收敛过去。活动项只影响**到达稳态的过程**。

**结论：代码保留（`reiActivityBaseline`，默认 0），但不采用。**

### 4.3 真正的旋钮：ρ、噪声、周期长度 —— 以及一个耦合陷阱

扫描结果（振幅 / 平滑后方向翻转次数 / 期末指数）：

| 配置 | 振幅 | 平滑翻转 | 期末指数 |
|---|---|---|---|
| 现状 ρ=.06 噪声8 幅46 | 57.0 | 25.3 | 119.5 |
| ρ=.15 噪声4 幅70 | 90.8 | 20.6 | — |
| ρ=.20 噪声4 幅90 | 134.5 | 20.5 | 140.0 |
| **一局一弧** ρ=.18 噪声4 幅90 T=32~55 | 137.3 | 21.1 | **63.6** |
| 一局一弧+更慢 T=40~70 | 130.9 | 22.2 | 82.8 |

**两个发现**：

1. **提高 ρ 是比调 `reiCycleAmp` 便宜得多的旋钮**：ρ 从 0.06 → 0.25（4.2 倍），
   振幅 59.7 → 82.0（+37%）。而调 `reiCycleAmp` 要 5.4 倍才换 2 倍振幅。

2. **"平滑后方向翻转"始终在 20~25 次**（35 季度的局 ≈ 每 1.8 季换一次方向）——
   也就是说 **REI 的形状基本是逐季抖动，从来没形成过连贯周期**。
   我第一轮说"周期被衰减"，更准确的说法是 **周期压根没成形**。

3. **"一局一弧"（T=32~55）的价值不在形状，而在结局**：
   期末指数从"稳定 119~140"变成"可能是 63" ——
   **周期相位终于能决定结局了**。这是"周期有意义"的实际判据。

### 4.4 ⚠️ 耦合陷阱：周期和追缴不能分开调

把上面那套"周期改造"直接上配对 A/B：

| 指标 | 现状 | 周期改造 | 差值 |
|---|---|---|---|
| **总分** | 0.9359 | **0.8772** | **−0.0587** ❌ |
| **追缴次数** | 0.49 | **9.27** | **+8.78（19 倍）** ❌❌ |
| 强制收回 | 0.09 | 2.45 | +2.36 ❌ |
| 现金占比 | 0.14 | **0.32** | +0.18 ❌ |
| 指数振幅 | 59.5 | 139.0 | +79.5 ✓ |

**REI 振幅一大，追缴概率就指数级上升**（阈值是"地价跌破抵押时的 66%"，
振幅越大越容易触发）。现金占比从 0.14 涨到 0.32 —— 玩家被逼着囤现金防爆仓。

**这反过来解释了现行 `reiRegression = 0.06` 为什么这么温吞：它很可能是被追缴频率倒逼出来的。**

**⇒ 要动周期，必须同步放宽 `marginCallRatio`（比如 1.10 → 1.35）。这是一个联合调参问题，单参数无解。**

## 五、建议顺序（按"实测支持度"排序）

| 顺序 | 方向 | 实测支持 | 成本 |
|---|---|---|---|
| **1** | **信用评级**（③） | 🟢 函数形式明确、传导链清楚 | 低-中 |
| **2** | **利率随周期**（②） | 🟢 阈值 = ratio×LTV，可精确预估 | 低 |
| **3** | **大区开发等级驱动股价**（① 的修正版） | 🟡 当季收入不可用（220% 噪声），改用慢变量 | 中 |
| ⚠️ | **周期改造** | 🔴 **实测 −0.0587；需与 `marginCallRatio` 联合调参，不能单独上** | 中-高 |
| ❌ | 做空（④） | 🔴 噪声主导 + 可操纵 | 高（不建议） |

**周期改造的下一步**（而不是直接上）：
先把 `marginCallRatio` 从 1.10 扫到 1.35~1.5，找到"追缴次数回到 0.5~5 区间"的值，
再连同 ρ / 噪声 / 周期长度一起做二维 A/B。**单参数扫描已经证明会翻车。**

## 附：如何复现

```powershell
node tools/fin-model.mjs 300        # 300 局，逐条对照模型与实测
node tools/fin-model.mjs 300 --amp  # 加跑周期振幅扫描（每档 120 局）
```

A/B 一律用配对种子（同一 `--seed` 跑两套配置），单次 150 局、跑 4 个种子取平均。
**模型改了之后必须重跑这些，否则你调的是自己的想象。**
