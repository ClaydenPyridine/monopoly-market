# 异地联机指南（朋友不在同一个 WiFi）

> 这份是专门讲**异地**的。局域网（同一个 WiFi）怎么玩见 [`给主机.md`](给主机.md)。
> 这里写的每一条都不需要改代码、不需要买服务器。

---

## 0. 三十秒决策

```
朋友和你不在一个 WiFi 下？
│
├─ 你们以后会经常一起开黑 ──────────→ 方案 A：Tailscale（每人装一次，之后一劳永逸）
│
├─ 就今晚玩一次，朋友懒得装东西 ────→ 方案 B：cloudflared（你装，朋友点链接就进）
│
├─ Tailscale 登录页打不开 / 装不上 ─→ 方案 C：ZeroTier 或 蒲公英（同类替代）
│
└─ 你家有公网 IP + 会弄路由器 ──────→ 方案 D：端口映射
```

**三个方案的共同点**：游戏本身不用改，房主照样双击 `启动-联机服务.bat`（或下面的专用 bat），
区别只在**怎么把那个 `192.168.x.x` 换成一个朋友能访问到的地址**。

| | 朋友要装吗 | 要公网 IP 吗 | 地址会变吗 | 速度 | 稳定性 |
|---|---|---|---|---|---|
| **A. Tailscale** | 要（一次性） | 不要 | 不会 | 最好（P2P 直连） | ★★★★★ |
| **B. cloudflared** | 不要 | 不要 | **每次重启都变** | 中（绕 Cloudflare） | ★★★☆☆ |
| **C. ZeroTier / 蒲公英** | 要（一次性） | 不要 | 不会 | 好 | ★★★★☆ |
| **D. 端口映射** | 不要 | **要** | 看运营商 | 最好 | ★★☆☆☆ |

## 1. 叫朋友之前，先自己验证（这步能省掉 90% 的扯皮）

不管用哪个方案，**在群里发链接之前**先做这两件事：

1. **本机自测**：浏览器打开 `http://127.0.0.1:8787/`，点「联机对战 → 创建房间」，能看到 4 位房间号 = 服务端没问题。
2. **外部自测（关键）**：**用手机关掉 WiFi、只开流量**，打开你准备发给朋友的那个地址（`100.x.x.x` 或 `https://xxx.trycloudflare.com`）。
   * 能看到「联机对战」按钮 = 通了，可以叫人了 ✅
   * 转圈 / 打不开 = 还没通，先按下面的排查走，别急着叫人 ❌

> 手机开流量就是一台"真正的外网设备"，这一步能验证掉防火墙、绑定地址、隧道这三类最常见的问题。
> 如果手机流量打不开但 WiFi 能打开，多半是**防火墙**问题，见第 5 节。

## 2. 方案 A：Tailscale（推荐，长期开黑用这个）

原理：给你们几个人的设备组一个**虚拟局域网**，之后就和坐在同一个 WiFi 下没区别。

### 房主做

1. 打开 <https://tailscale.com/> → Download → 装 Windows 版
2. 装完托盘里会出现图标，点它 → **Log in**，用 Google / GitHub / 微软账号登录（免费版够用：3 个用户、100 台设备）
3. 记下自己的 Tailscale 地址：托盘图标点开就能看到 `100.x.x.x`，或者在终端跑
   ```powershell
   tailscale ip -4
   ```
4. 双击 `启动-联机服务.bat`（老一套，不用变）
5. 把 **`http://100.x.x.x:8787/`** 发给朋友（把 `100.x.x.x` 换成第 3 步查到的）

### 朋友做

1. 同样去 <https://tailscale.com/> 下载安装
2. **登录同一个账号**（最省事），或者让房主在后台邀请你的邮箱加入同一个 tailnet（更规范，各自用自己的账号）
3. 托盘图标变成 **Connected** 之后，浏览器打开房主发的 `http://100.x.x.x:8787/`
4. 点「联机对战」→ 输房间号 → 进

### 注意

* **必须确认托盘图标是 Connected**，显示 `Stopped` 就打不开，点一下登录即可。
* 免费的 **Quick Tunnel 不需要**，Tailscale 不需要任何端口映射、不需要公网 IP。
* 想用机器名代替 IP（比如 `http://房主的电脑名:8787/`），需要在管理后台打开 **MagicDNS**。
* 国内访问 tailscale.com 的控制面偶尔会慢或打不开，**登录成功之后**的连接是设备间 P2P 直连的，通常很流畅；实在登不上就换方案 C。
* 用不上的时候可以在托盘里 Disconnect，不影响正常上网。

## 3. 方案 B：cloudflared（朋友零安装，适合临时凑一次）

原理：把本机的 8787 端口**映射成一个公网网址**，朋友点链接就进。

### 准备（房主，已经帮你做好了）

`cloudflared.exe` **已经下载好放进游戏文件夹了**（52.8 MB，版本 2026.10.0，
Windows 数字签名验证通过，签发者是 `Cloudflare, Inc.`）。**你不用再下任何东西。**

> 想自己确认一下：右键 `cloudflared.exe` → 属性 → 数字签名，应该能看到「Cloudflare, Inc.」的有效签名。
> SHA256：`86AEE4017B26625CEE8484C113558F48EFFA4CD47F7AA05FCF425604E5D2B23C`

### 每次开黑：双击一个文件，然后照抄框里的网址

**双击 `启动-异地联机-cloudflared.bat`**，窗口里会依次显示 `[1/3] [2/3] [3/3]`，对应它自动做的三件事：

1. `[1/3]` 另开一个窗口启动游戏服务器
2. `[2/3]` 自动打开浏览器进游戏（`http://127.0.0.1:8787/`）
3. `[3/3]` 建立公网隧道

等 10~20 秒，**装着隧道的那个窗口**里会出现一个方框：

```
  ╔════════════════════════════════════════════════════════════════╗
  ║   把下面这一整行，原样复制发给朋友：                            ║
  ║                                                                ║
  ║   https://rest-actively-jpg-regression.trycloudflare.com       ║
  ║                                                                ║
  ║   朋友：点开这个网址 → 联机对战 → 输房间号 → 加入房间           ║
  ║   你： 本机浏览器点「联机对战 → 创建房间」，把房间号也发过去     ║
  ║   ! 两个黑窗口都别关；关掉任何一个，朋友都会掉线。             ║
  ╚════════════════════════════════════════════════════════════════╝
```

**只复制框里那一行网址**发出去就行。

> 这个方框是 `tools/tunnel.mjs` 打印的。cloudflared 原生日志把网址混在一堆 `INF |` 行里，
> 而且启动早期还会出现 `api.trycloudflare.com` 这种干扰项，所以脚本会**等 "quick Tunnel has been created"
> 那行出现之后**才取网址，避免给你一个废链接。

**实测**：抓到的网址 `/` 和 `/src/ui.js` 都返回 HTTP 200，约 1~2 秒；POST 偶尔会 `Connection reset`，
游戏客户端已内置 8 秒超时 + 3 次自动重试（实测 4/4 都在第 1 次就通）。

### 手动方式（想自己敲命令的话）

```powershell
# 第一个窗口
node server.mjs

# 第二个窗口（同一个文件夹，Shift+右键 → 在此处打开 PowerShell）
.\cloudflared.exe tunnel --url http://127.0.0.1:8787
```

### 这个方案的坑（务必知道）

| 坑 | 说明 |
|---|---|
| **链接是公开的** | 任何拿到链接的人都能打开游戏页面、能创建/加入房间。房间号算一道小门槛，但**别把链接发到公开群/论坛**，玩完就把窗口关掉 |
| **网址每次都会变** | 免费 Quick Tunnel 没有固定域名，关掉重开就是一个新网址，得重新发 |
| **房主不能关窗口** | `cloudflared` 那个窗口和游戏服务器窗口，关掉任何一个朋友就掉线 |
| **电脑休眠就断** | 记得把电源计划设成"从不睡眠" |
| **偶尔抽风** | 免费隧道没有 SLA。**游戏客户端已经内置 8 秒超时 + 自动重试 3 次**，重试用同一个请求编号、服务端认得出不会重复执行，所以基本感觉不到；万一还是失败会弹一句"请再点一次" |

### 实测数据：cloudflared 到底靠不靠谱

我在你这台机器上真测过：

| 测试项 | 结果 |
|---|---|
| 强制走 **IPv4** 的 GET / POST | **10 / 10 全通**，约 1~2 秒 |
| 强制走 **IPv6** | **0 / 10 全挂**（这台机器到 Cloudflare 的 IPv6 路径不通） |
| 默认（让程序自己挑） | 15 / 20 —— curl 有时会挑到那条坏的 IPv6 |
| **SSE 长连接**（早期版本用的传输方式） | **本机回环首帧立刻到；走公网隧道 20 秒 0 字节** ← 曾经的致命坑 |
| **长轮询**（现在用的方式） | 挂起 4 秒后触发开局，**1 秒内被唤醒**，状态包 12.6 KB 完整送达 ✅ |

**两个结论：**

1. **IPv6 问题在你这边**：隧道本身没问题，是这台机器到 Cloudflare 的 IPv6 不通。浏览器有 Happy Eyeballs（IPv4/IPv6 同时试、谁先通用谁），实际体验比 curl 测出来的好得多；客户端另有 8 秒超时 + 3 次重试兜底。如果朋友那边也卡，让他在路由器里关掉 IPv6。

2. **Cloudflare Quick Tunnel 会把 SSE 缓冲住** —— 这是早期版本"房主已开局、其他人还没进游戏"的真正原因（原来用 `EventSource` 收状态）。**现在游戏改用长轮询**，它是一个普通的完整 HTTP 响应，任何隧道/代理都过得去，所以 cloudflared 这条路现在是通的。

> 顺带说明：如果你改用 ZeroTier / Tailscale / EasyN2N 这类虚拟局域网，它们是**透明 TCP 层**，SSE 和长轮询都能过，不存在这个坑。

### 想要固定网址？

用 cloudflared 的**正式 Tunnel** + 你自己的域名（域名托管在 Cloudflare）：
```powershell
cloudflared tunnel login
cloudflared tunnel create dizhu
cloudflared tunnel route dns dizhu game.你的域名.com
cloudflared tunnel run --url http://127.0.0.1:8787 dizhu
```
这样网址就固定成 `https://game.你的域名.com` 了。需要你有域名，其余仍然免费。

## 4. 方案 C：ZeroTier / 蒲公英（Tailscale 装不上时的替代）

和 Tailscale 一个思路（虚拟局域网），只是换了个服务商。

**ZeroTier**（<https://www.zerotier.com/>）
1. 房主注册 → Create A Network → 记下 **Network ID**（16 位）
2. 所有人的客户端里 Join Network，填那个 ID
3. 房主在后台把每个加入的设备勾上 **Auth**（授权）
4. 房主查自己的 ZeroTier 地址（通常是 `192.168.19x.x` 或 `10.x`），跑 `启动-联机服务.bat`
5. 朋友打开 `http://房主的ZeroTier地址:8787/`

**蒲公英**（<https://pgy.oray.com/>，国产，中文界面）
1. 所有人注册账号 → 组网 → 互相加入同一个网络
2. 直接用分配到的虚拟 IP 访问 `http://虚拟IP:8787/`

国内网络环境下，这两个的**登录/控制面**通常比 Tailscale 稳一点。

## 5. 方案 D：端口映射（有公网 IP 时）

1. 确认你有公网 IP：百度搜"IP"，看结果和路由器 WAN 口的 IP 是否一致。**不一致 = 运营商大内网（NAT），这条路走不通**，回去用方案 A。
2. 路由器后台 → 端口转发 / 虚拟服务器 → 把 **TCP 8787** 转发到房主电脑的内网 IP。
3. 查房主电脑的内网 IP：终端跑 `ipconfig`，看 IPv4 地址（`192.168.x.x`）。
4. 建议给房主电脑设一个**静态内网 IP**，否则重启后 IP 变了转发就失效。
5. 朋友访问 `http://你的公网IP:8787/`。

⚠️ 直接把端口暴露在公网上，任何人都能扫到并打开你的游戏页面。玩完建议把转发规则关掉。

## 6. 排查表（按顺序试）

| 现象 | 最可能的原因 | 怎么办 |
|---|---|---|
| 房主自己都打不开 `127.0.0.1:8787` | 服务端没起来 | 看黑窗口有没有报错；`EADDRINUSE` 就换端口 `node server.mjs 8899` |
| 本机能开，手机流量打不开 | **Windows 防火墙拦了** | 设置 → 网络和 Internet → 防火墙 → 允许应用通过防火墙 → 找到 **Node.js** → 勾上「专用」**和「公用」**；或者干脆临时关掉防火墙试一下 |
| Tailscale 装了但打不开 | 没登录 / 显示 Stopped | 托盘图标点开登录；确认双方在**同一个 tailnet** |
| Tailscale 登录页打不开 | 控制面被墙/抽风 | 换个网络登一次，或者改用 ZeroTier / 蒲公英 |
| cloudflared 报 `failed to request quick Tunnel` | 连不上 Cloudflare | 检查本机能不能上网；重跑一次；换个时间段 |
| 朋友能打开页面，但进不了房间 | 房间号错了 / 房间满了 | 让房主重新念一遍房间号；**房间满了等下一局，或者用下面的「中途加入」顶替一台电脑** |
| **房间已经开局了还想加人** | 开局后不接受新玩家 | 只要房里还有**纯电脑座位**，大厅里会出现「**中途加入（顶替电脑座位）**」按钮，点它就能坐进去。掉线玩家的座位带标记，抢不走 |
| 能玩但很卡、走子一顿一顿 | 走了中继（DERP）或绕了 Cloudflare | Tailscale 里看连接类型，能 P2P 就快了；cloudflared 天生慢一些，回合制游戏一般能忍 |
| 玩到一半突然全掉线 | 房主电脑睡眠 / 关了窗口 / 网断了 | 把电源计划设成"从不睡眠"；重启两个窗口，**大家刷新页面就会自动回到各自的座位** |
| **某个人掉线了，会不会卡住** | 不会 | 轮到他、且静默超过 **60 秒**，电脑会自动接管他的座位，别人继续玩；他回来刷新一下就交还。掷骰/买地类还有 **90 秒**、交易阶段 **180 秒**的回合超时兜底，超时走最保守动作（**绝不替他花钱**）|
| 朋友的座位没了 / 想换个设备接着玩 | 换了浏览器或清了数据 | 直接刷新会**自动回座位**；认不回来就点「联机对战」→ 输**房间号 + 原来那个名字** → 加入房间 |

## 7. 速度上到底行不行？

回合制棋盘游戏**每次操作只发一个几十 KB 的包**，对带宽和延迟都不敏感：

* **Tailscale**：绝大多数情况是设备间 P2P 直连，延迟和你平时上网差不多，体验和局域网几乎无差别。
* **cloudflared**：所有流量绕一圈 Cloudflare 边缘节点，国内可能多 100~300ms。掷骰子时的棋子动画会稍微顿一点，但**完全不影响操作和判定**。
* 真正影响体验的是**房主的上传带宽**，而这个游戏对上传的要求极低（4 个人同时在线也就几十 KB/s）。
