## 1. 方法论（可复现）

### 1.1 为什么不靠肉眼、也不靠读 CSS

肉眼看不准"差 3px 还是 30px"，读 CSS 也推不准 flex/grid 的实际收缩结果
（本轮最大的两个发现——`.slots` 的 284px min-content 下限、`--sz: 1.1vw` 与格子宽度脱钩——
都不是读 CSS 能看出来的）。所以用 **headless Edge + CDP** 把游戏真跑起来，
等页面稳定后注入测量脚本，直接从 DOM 拿数字。

### 1.2 命令

```powershell

# 全矩阵（7 个分辨率 × 33 个场景 ≈ 231 次运行，单浏览器约 12 分钟）
$env:PAGE = "$env:TEMP\layout-audit\snapshot2\地产股神.html"   # 指向冻结快照，保证可复现
node tools/audit-layout.mjs --out="$env:TEMP\layout-audit\F" --json="$env:TEMP\layout-audit\F.json"

# 只跑某几个分辨率/场景（并行提速：不同 --port 会自动用不同 profile 目录）
```

`--list` 列出全部场景与分辨率；`--emit-js=文件` 把测量脚本单独导出，可直接贴进 DevTools Console 手动复现。
环境变量：`EDGE_PATH` 覆盖 msedge.exe 路径，`PAGE` 覆盖被测 HTML。

### 1.3 测量脚本判据（都写在 `MEASURE` 里）

| 判据 | 实现 |
|---|---|
| 内容溢出 | `scrollHeight > clientHeight + 2` 且 `overflow-y: visible`（滚动容器不算，那是设计） |
| 文字被压没 / 被裁 | `overflow: hidden` 且 `scrollHeight > clientHeight + 2` 且无子元素 → 顺带记 `可见高度只剩 ch/sh%` |
| ellipsis 截断 | `text-overflow: ellipsis` 且 `scrollWidth > clientWidth + 1` |
| 真·文字压叠 | 遍历所有文本节点取 `Range.getBoundingClientRect()`，**先按祖先 `overflow` 与视口裁剪**，再两两求交；`ov>1px 且面积>4px²` 才算 |
| 元素遮挡 | 有底色/边框的盒子两两求交，**同样先裁剪** |
| 上层遮罩误报 | 交叠区中心 `elementFromPoint`：若最上层元素落在 `.modal-mask / .overlay / #bottom.expanded / .drawer.open / .toast / #net-banner` 里，而两个元素不都在同一个遮罩里 → 判为"被盖住"，不算缺陷 |
| 出界 | 可见矩形超出视口 2px 以上 |
| 滚动不可达 | 滚动容器 `scrollTop=0` 时仍有后代被切在容器**顶边之外**（CSS 起始方向溢出不可滚动） |

### 1.4 三个必须做、否则数据是错的工程处理

1. **动画结算**（`FREEZE_SRC`，默认开启）
   headless (`--disable-gpu`) 在没有合成帧时不推进 CSS 动画时间轴，元素会**一直停在 `@keyframes` 的 `from` 状态**。
   实测后果：棋子的 `tkpop` 是 `from { transform: scale(.2) }`，量出来是 `19 × 0.2 = 3.8px`，
   看起来像"棋子小到看不见"。测量前 `document.getAnimations().forEach(a => a.cancel())` 让它落到稳定态再量。
   排查动画本身时用 `--no-freeze-anim` 关掉。
2. **清 localStorage**（`Page.addScriptToEvaluateOnNewDocument`）
   `UI.toggleCenter()` 会把折叠状态写进 `localStorage['dgs-center-mini']`，而 headless 用持久 profile ——
   跑过一次 `?mini=1` 之后，**后面所有场景都带着"已折叠"渲染**。不清就是脏数据。
3. **就绪闸门**（`READY_SRC`）
   dist 单文件 1.9MB，多浏览器抢 CPU 时 `navigate` 后 5 秒脚本可能还没跑完，
   注入 `UI.g.pending = …` 会直接 `ReferenceError: UI is not defined`（实测在
   `buy-modal@1280x720`、`buy-modal@1024x768`、`stress-all@1920x1080` 上各出现过一次）。
   现在会轮询到 `UI 已定义 && readyState==='complete' && (设置页可见 || 40 个格子已建好)` 再注入。

## 2. 缺陷清单

### 🔴 D1 开局设置页 `.slots` 横向溢出 39px

- **出现条件**：开局设置页（不带 `auto=1`）。**7/7 分辨率都实测到**，与分辨率无关。
- **量到的数字**（定点测量，7 个分辨率数值完全一致）：

  | 元素 | clientWidth | scrollWidth | 超出 |
  |---|---|---|---|
  | `#setup .setup-card` | 540 | **579** | 39px |
  | `#slots` | 540 | **579** | 39px |
  | 单个 `.slot` | — | 实测 **284px** 宽（应为 (540−11)/2 = 264.5） | 19.5px |

- **截图**：`%TEMP%\layout-audit\F3\setup_1280x720.png`
  直观表现：两条 slot 行整体比卡片宽 39px、只向右溢出，右列的「人类/电脑/不参与」下拉框
  探出卡片右边缘约 40px；slot 行与标题、提示文字、下面的「游戏时长/初始现金」不在同一条中轴线上。
- **根因（CSS）**：`styles.css` 快照第 1014 行
  ```css
  .slots { display: grid; grid-template-columns: 1fr 1fr; gap: 11px; }
  ```
  `1fr` 等价于 `minmax(auto, 1fr)`，这个 `auto` 下限取**条目的 min-content**。
  而 `.slot` 是 flex 行（第 1015 行），它的 min-content 是各项 min-content 之和：
  ```
  dot 15 + gap 10 + input 151 + gap 10 + select 70 + padding 26 = 282 ≈ 284
  ```
  关键点：`.slot input { min-width: 0 }`（第 1027 行）**只解除 flex 自动最小尺寸，不改变它对容器
  min-content 的贡献** —— `<input type="text">` 的 min-content 等于它的内在宽度（默认 `size=20` ≈ 151px），
  而 `select` 是 `min-width: auto`（70px，最宽选项「不参与」）。
  于是两条轨道最小 284×2 + 11 = **579 > 540**，`fr` 无法再分配，直接溢出。
- **建议修法**（一行）：
  ```css
  .slots { grid-template-columns: repeat(2, minmax(0, 1fr)); }
  ```
  `minmax(0, 1fr)` 把下限压到 0，轨道回到 264.5px，input 靠 `min-width:0` 收缩到约 133px，不再溢出。
  加固项：`.slot input { width: 100% }`；`select { min-width: 0 }` 视需要。

### 🟡 D2 长玩家名把顶栏撑高，棋盘超出容器 12px

- **出现条件**：玩家名很长（联机可任意改名）+ 窗口较窄（1024×768 / 900×700）。
  命中运行：`longname@1024x768`、`longname-mini@1024x768`、`longname@900x700`、
  `longname-mini@900x700`、`longname-drawers@900x700`、`tokens-4-all@900x700`、`stress-all@900x700`
- **量到的数字**：
  - 1024×768：`#boardwrap` clientHeight **546** / scrollHeight **558**（超 12px）
  - 900×700：`#boardwrap` clientHeight **478** / scrollHeight **490**（超 12px）
  - 对照：同一个 1024×768，普通名字时 `#boardwrap` 546/546（不溢出）；顶栏高度 51px → **90px**
- **截图**：`%TEMP%\layout-audit\F3\longname_1024x768.png`
  可见「当前玩家」药丸里的名字换成 3 行、顶栏整体变高，「季度 / 地产指数」标签被挤成竖排换行。
  棋盘上下各溢出 6px —— 本次被 `main` 的 14px padding 吸收了（实测棋盘底边 y≈655、日志顶边 y≈663，还差 8px），
  **没有真的压到日志**；但余量只剩 8px，再多一行名字就会撞上。
- **根因（CSS）**：
  - 快照第 213 行 `#board { width: min(100%, calc((100vh - 210px) * 1.5)); aspect-ratio: 3 / 2; }`
    —— 高度被钉死成 `100vh − 210px`，而 210px 是按「顶栏 52 + 底栏 104/128 + padding 28」算出来的常数，
    只留了约 26px 余量；顶栏一涨就穿。
  - `#topbar .topstats .ts b`（第 89–97 行）没有任何 `max-width`/`overflow`/`ellipsis`，
    长名字直接换行把药丸撑成 3 行。
- **建议修法**：
  1. 别再算 `vh` 常数，让棋盘跟着容器走（`#boardwrap` 已有 `min-height:0` + `place-items:center`）：
     ```css
     #board { height: 100%; width: auto; max-width: 100%; aspect-ratio: 3 / 2; }
     ```
  2. 顶栏做防爆：
     ```css
     .topstats { min-width: 0; }
     .ts { min-width: 0; }
     .ts b { max-width: 22ch; overflow: hidden; text-overflow: ellipsis; white-space: nowrap; }
     ```

### 🟡 D3 折叠排行榜的金额列装不下 10 位数

- **出现条件**：中央面板折叠 + 现金到 10 位数（脚本注入 `¥1,234,567,890`）。**7/7 分辨率都命中**
  （1920/1600/1440/1366/1280/1024/900 的 `bigcash-mini`）。
- **量到的数字**：
  - `.mini-rank .mr-row.lead > b.mr-v`：scrollWidth **92** / clientWidth **82**（超 10px）
  - `.mini-rank .mr-row.lead` 与 `#mini-rank`：scrollWidth **587** / clientWidth **581**（把面板也顶宽了）
- **截图**：`%TEMP%\layout-audit\F3\bigcash-mini_1024x768.png`
- **根因（CSS）**：快照第 539 行
  ```css
  .mini-rank .mr-row { display: grid; grid-template-columns: 16px 12px 1fr 90px 82px; gap: 8px; }
  ```
  最后一列固定 82px，而 `.mr-v`（第 551 行）只有 `text-align: right`，
  **没有 `overflow`/`ellipsis`**，`fmt()` 出来是 `¥1,234,567,890`（约 92px）→ 直接溢出列外并顶出面板 padding。
- **建议修法**（任选其一，建议 1+3）：
  1. `.mini-rank .mr-v { min-width: 0; overflow: hidden; text-overflow: ellipsis; white-space: nowrap; }`
  2. 把最后一列改成 `minmax(0, 82px)`，或 `auto`
  3. 金额用已有的 `fmtShort()`（≥10 万显示「万」）——迷你排行榜本来就是概览

### 🟡 D4 4 人挤同一格时棋子横向溢出、被格子裁掉

- **出现条件**：4 名玩家在同一格 + 窗口**宽而矮**（高度 ≤ ~720 且宽度较大）。
  断点探针实测：`tokens-4` / `tokens-4-drawer` 在 **1440×699、1440×700、1440×701 六个运行全部命中**
  （`.tokens` scrollWidth 64 > clientWidth 58，超 6px，达阈值）；
  1440×861/860/859 与 1440×820 不命中；1280×720 是**临界**（`.tokens` 61/62、最左棋子左缘 845 vs
  容器左缘 846，超 1px，未达脚本的 2px 阈值所以矩阵没标出来）。
- **量到的数字**（动画已结算，4 枚棋子都是完整尺寸）：

  | 分辨率 | 格子宽 | 棋子尺寸 | `.tokens` cw/sw | 首枚左缘 vs 容器左缘 | 末枚右缘 vs 格子右缘 |
  |---|---|---|---|---|---|
  | 1920×1080 | 114.1 | 19.0 | 110/110 | 1351 ≥ 1337 ✓ | 1433 ≤ 1449 ✓ |
  | 1440×820 | 78.6 | 15.83 | 75/75 | 976 ≥ 973 ✓ | 1044.8 ≤ 1049.6 ✓ |
  | **1440×700** | **62.3** | **15.83** | **58/64** | 910 vs 916 ✗ | **979.8 > 976.3（出格 3.5px，被裁）** |
  | 1280×720 | 65.0 | 14.08 | **61/62** | 845 vs 846 ✗（左溢 1px） | 907.1 ≤ 909 |
  | 1024×768 | 71.5 | 11.25 | 68/68 | ✓ | ✓ |
  | 900×700 | 62.3 | 11.0 | 58/58 | ✓ | ✓ |

- **截图**：`%TEMP%\layout-audit\CROP\tokens-4_1440x700_zoom.png`（6× 放大）
  可见「蒙德城」格子里 4 枚棋子，**最左（1 号）和最右（4 号）各被格子边缘切掉一块**。
- **根因（CSS）**：棋子尺寸跟**视口宽度**走、格子尺寸跟**视口高度**走，两者在宽而矮的窗口里脱钩：
  - 快照第 353 行 `.tk { --sz: clamp(11px, 1.1vw, 19px); flex: none; }` → 1440 宽时 1.1vw = 15.83px
  - 快照第 213 行 `#board` 由 `100vh − 210px` 决定高度 → 700 高时格子只有 62.3px 宽
  - 快照第 348 行 `.tokens { left:1px; right:1px; bottom:1px; display:flex; flex-wrap: nowrap; justify-content: center; }`
    4 × 15.83 + 3 × 2(gap) = 69.3px > 58px 可用宽度，`nowrap` + `center` 把两侧棋子对称推出格子，
    再被 `.tile { overflow: hidden }` 裁掉。
  `flex: none` 本身是对的（防止被压成 3px），问题在尺寸依据选错了轴。
- **建议修法**：把棋子尺寸绑到**格子尺寸**（格子尺寸跟着棋盘高度走），例如：
  ```css
  /* 格高 ≈ (100vh − 258px) / 11；4 枚 + 3 个 2px gap 必须塞进 格宽 − 2 */
  .tk { --sz: clamp(10px, calc((100vh - 258px) * 0.02), 19px); }
  ```
  或者退一步：`@media (max-height: 780px) { .tk { --sz: clamp(10px, 1.0vw, 13px); } }`
  （1440×700 下变成 13px：4×13+6 = 58 ≤ 58，刚好塞下）。
  另一个方向是允许换行：`.tokens { flex-wrap: wrap }` —— 但 62px 宽的格子里两行棋子会压到地名，
  所以更推荐缩尺寸。

### 🟡 D5 折叠态中央面板 `.rei-box` 内容比盒子高 3px

- **出现条件**：中央面板折叠（`?mini=1` 或按 `C`）。**7/7 分辨率都命中**（F1 12/66、F2 12/66、F3 12/66、F4 6/33）。
- **量到的数字**：`#center-grid > .rei-box` scrollHeight **30** / clientHeight **27**（超出 3px，可见高度只剩 90%）
- **根因（CSS）**：快照第 501 行 `.center-grid.mini .rei-value { font-size: 26px }`，
  而第 557 行 `.rei-value { line-height: 1.02 }` → 行盒 26.5px；mini 态 `.rei-box` 是 flex 行（第 492 行），
  高度被压到 27px，可 `#rei-value` 的字形盒需要 30px。
- **影响**：溢出的 3px 落进下方 `gap: 8px` 里，**没有压到相邻内容**，属临界项。
- **建议修法**：`.center-grid.mini .rei-value { line-height: 1.15 }`，或 `.center-grid.mini .rei-box { min-height: 30px }`。

### 🟡 D6 中央面板顶部 4.9px 被切且滚不回来

- **根因（CSS）**：快照第 434 行
  ```css
  #center { display: grid; place-items: center; overflow-y: auto; }
  ```
  内容高于容器时 `align-items: center` 会把溢出平摊到上下两侧，而 **CSS 起始方向（上边）的溢出不可滚动**，
  于是顶部那部分永远看不到。抽屉展开时棋盘变成宽度受限（1024 下可用宽 592 < 837），
  格子行高掉到 ~31px，中央面板内容因此变高，正好触发。
- **建议修法**：
  ```css
  #center { place-items: start center; }      /* 或 align-items: start */
  /* 想保留居中又不要"不可达"，用 safe： place-content: safe center; */
  ```

### 🟢 D7 迷你排行榜超长玩家名被 ellipsis 截断

- 条件：超长名 + 中央折叠。数字：`.mr-n` scrollWidth **468** / clientWidth **341**。
- 这是 `.mr-n { text-overflow: ellipsis }`（第 548 行）**设计如此**，截断后仍有名字前缀可辨认，判为可接受。
  若要更好，可在折叠榜里用「名字前 6 字 + …」而不是纯 CSS 截断。

### 🟢 D8 `#rei-value` 行盒比内容矮（字体度量交叠，视觉无压字）

- 数字：1920×1080/1600×940 时 `#rei-value` scrollHeight **53** / clientHeight **47**；
  1280×720/900×700 时 **37/33**。
- 与 `#rei-sub`、`#rei-mult`、`.rei-label` 的文本矩形交叠 4.4~6.1px（纵向占比 0.31~0.44）。
- **已用 5× 放大截图复核**（`%TEMP%\layout-audit\CROP\play-roll_1280x720_zoom.png`、以及上一轮的
  `Z3` 1920×1080 图）：**字的像素完全没碰到**，大号数字与下方说明之间留有可视空隙。
  交叠来自 `line-height: 1.02` 下字体 ascent/descent 盒超出行盒 —— 属于"行盒级"交叠，不是"字形级"压叠。
- 想让报告彻底干净可改：`.rei-value { line-height: 1.15 }` 或 `.rei-sub { margin-top: 2px }`。**不改也不影响可读性**。

### 🟢 D9 有棋子格的地名行盒 1px 取整差

- 数字：1920×1080 与 1440 系下 `.nm` clientHeight **12** / scrollHeight **13**（1440×700 为 11/12）。
- 原因：`font-size: clamp(8px,.68vw,10.5px)` × `line-height: 1.15` = 12.075px，`clientHeight` 向下取整、
  `scrollHeight` 向上取整。**不是真裁剪**（实测「地名被裁的格子 = 0」，40/40 完全可见），无需处理。

- **1024×768**：棋盘 **837×558**，可用宽 = 1024 − 18 − 90 = **916** → 837 < 916，仍是**高度受限**，
  不是被宽度卡死。格子 71.5×46.2（旧正方形方案是 40.2×40.2）→ 行高不变、列宽 ×1.5，符合改造意图。
- **900×700**：棋盘 **735×490**，可用宽 = 900 − 18 − 90 = **792** → 735 < 792，仍是**高度受限**。
  格子 62.3×40（旧 40.2×40.2）。
- 宽度开始成为瓶颈的临界线是 `W < 1.5H − 207`（H=768 → 945；H=700 → 843），

### 3.3 断点两侧没有"半开半关"的怪状态

## 4. 附：测量脚本用法

脚本：`tools/audit-layout.mjs`（零依赖，用 Node 24 的自带 `WebSocket` + Edge 的远程调试端口）。

```powershell
node tools/audit-layout.mjs --list                       # 列出所有场景/分辨率
node tools/audit-layout.mjs                                # 全矩阵（7 分辨率 × 33 场景）
node tools/audit-layout.mjs --probe                        # 只跑 6 个断点探针分辨率
node tools/audit-layout.mjs --scenario=tokens-4 --viewport=1440x700,900x700
node tools/audit-layout.mjs --scenario=bigcash-mini --viewport=1280x720 --jitter
node tools/audit-layout.mjs --scenario=setup --viewport=1920x1080 --eval="..."
node tools/audit-layout.mjs --scenario=play-roll --viewport=1280x720 --crop=x,y,w,h --crop-scale=5
node tools/audit-layout.mjs --emit-js=%TEMP%\measure.js       # 导出测量脚本，贴进 DevTools 手动跑
```

主要开关：

| 开关 | 作用 |
|---|---|
| `--viewport=a,b` / `--scenario=a,b` | 逗号分隔，可多选 |
| `--probe` | 只跑断点探针分辨率（配 `PROBE_SCENARIOS`） |
| `--jitter` | 跑完再采 11 次矩形，报动画造成的布局位移（按元素身份配对，避免下标错位假位移） |
| `--crop=x,y,w,h` + `--crop-scale=N` | 截图裁到指定区域并放大，肉眼复核"字到底碰没碰" |
| `--eval=<js>` | 加载完成后跑任意 JS 并打印（已等就绪 + 已结算动画） |
| `--settle=倍数` | 整体缩短/加长等待（默认 1） |
| `--no-freeze-anim` | 不结算 CSS 动画（排查动画本身时才用） |
| `--out=目录` / `--json=文件` | 截图目录 / 原始 JSON |
| `--port=N` | 远程调试端口；**不同端口自动用不同 profile 目录**，可以并行开多个浏览器 |
| `--keep-open` | 跑完不关浏览器（调试用） |

输出：每个 (场景 × 分辨率) 一行计数 + 跨分辨率去重的缺陷签名分组 + 原始 JSON（含每条命中的
选择器、矩形、`clientHeight/scrollHeight`、理由文本）。
截图落在 `--out` 目录，命名 `<场景>_<分辨率>.png`。

> 注意：Windows 上 `proc.kill()` 只杀父进程，Edge 的 gpu/renderer 子进程会残留
> （实测跑几个场景留下 80+ 个进程）。脚本内部用 `taskkill /T /F`（`spawnSync`，同步执行）连子孙一起收；
> 如果中途 Ctrl+C 或强杀 node，仍可能漏，手工清理时请只杀命令行里带 `layout-audit` 的 msedge 进程，
> 别误伤自己的浏览器：
> ```powershell
> Get-CimInstance Win32_Process -Filter "Name='msedge.exe'" |
>   Where-Object { $_.CommandLine -like '*layout-audit*' } |
>   ForEach-Object { taskkill /F /PID $_.ProcessId }
> ```
