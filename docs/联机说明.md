# 联机说明（3~4 人，可加电脑）

联机是**房主开服**的模式：一个人在自己电脑上跑一个零依赖的小服务端，其他人用浏览器连进来。
房主那台机器上的程序是唯一权威——回合顺序、股价、骰子、AI 全在它那里算，作弊不了。
别人掉线或者发呆也不会把整局卡死：服务端有**回合超时**和**掉线托管**兜底（见第四节）。

---

## 一、同一个 WiFi 下玩（最省事，推荐）

### 房主做三件事

1. 在这个文件夹里打开一个终端，跑：

   ```powershell
   node server.mjs
   ```

   终端会打印出三个地址，长这样：

   ```
     地产股神 · 联机服务已启动
     ─────────────────────────────────────────
     本机：      http://127.0.0.1:8787/
     局域网：    http://192.168.1.23:8787/    ← 同 WiFi 的朋友用这个
     ─────────────────────────────────────────
   ```

2. 自己用浏览器打开 `http://127.0.0.1:8787/`，点 **联机对战 → 创建房间**，
   屏幕上会出现一个 **4 位房间号**（比如 `GY9R`）。

3. 把 `http://192.168.1.23:8787/`（换成你终端里显示的那个局域网地址）和房间号发到群里。

> 第一次跑的时候 Windows 会弹防火墙提示，**选「允许访问」并勾上「专用网络」**，否则朋友连不上。

### 其他人做两件事

1. 浏览器打开房主发来的那个 `http://192.168.x.x:8787/` 地址。
2. 点 **联机对战 → 输入房间号 → 加入房间**，填个名字。

### 开局

四个人（或更少）都进了房间后，房主在房间里选 **人数（2/3/4）** 和 **季度数**，点 **开始游戏**。
**空位会自动补上电脑**（电脑·老王 / 阿May / 铁柱 / 小满），所以 2 个人也能开一局。

## 二、异地远程玩

局域网地址（192.168.x.x）出了家门就没了。异地有两种办法，都不用改代码。

### 方案 A：Tailscale（推荐，最稳、免费）

原理：给你们几个人的设备组一个虚拟局域网，之后就像在同一个 WiFi 下一样。

1. 所有人去 <https://tailscale.com/> 下载安装，注册并登录 **同一个账号**（或者互相邀请进同一个 tailnet）。
2. 房主跑 `node server.mjs`，在 Tailscale 托盘图标里看自己的 **100.x.x.x** 地址，或者直接跑 `tailscale ip -4` 查。
3. 其他人浏览器打开 `http://100.x.x.x:8787/`。

优点：不用公网 IP、不用端口映射、流量加密、地址固定。
缺点：每个人都要装一次客户端。

### 方案 B：cloudflared（朋友零安装，但要联网且有公共链接）

原理：把本机的 8787 端口映射成一个临时公网网址。

1. 房主下载 <https://developers.cloudflare.com/cloudflare-one/connections/connect-networks/downloads/> 的 `cloudflared`。
2. 跑：

   ```powershell
   cloudflared tunnel --url http://127.0.0.1:8787
   ```

3. 终端会打印一个 `https://xxxx-xxxx.trycloudflare.com` 的地址，把这个发给朋友就行。

优点：朋友什么都不用装，点链接就进。
缺点：**这个链接是公开的**，谁拿到都能打开页面（房间号算一道小门槛，但别把链接发到公开场合）；房主的电脑关机就断。

### 方案 C：端口映射（有公网 IP 时）

在路由器上把 **TCP 8787** 映射到房主电脑的内网 IP，然后大家访问 `http://你的公网IP:8787/`。
注意家里宽带多半是运营商大内网（NAT），这种办法经常不生效——不行就用方案 A。

## 三、玩的时候会是什么样

| 事情 | 表现 |
|---|---|
| 轮到谁 | 只有当前玩家的按钮是可点的，其他人屏幕上显示「等待 XX 行动…」 |
| 掷骰子 / 走棋子 | 所有人的棋子会**同时**动起来，骰子也会一起滚 |
| 你落地要买地 | **只有你**弹出买地窗口，别人只看到棋盘变化 |
| 股票 | **不用等轮到你**，任何人的回合都能点右侧「股市」买卖股票（例外见下） |
| 金融产品 / 升级 / 抵押 | 还是在自己的交易阶段（掷完骰子之后）操作，别人看不到你在看什么 |
| 轮到你的时候 | 屏幕上有**倒计时**（掷骰/买地/事件/监狱 90 秒、交易阶段 180 秒），剩 30 秒变琥珀色提醒 |
| 超时了 | 服务端替你执行**最保守的动作**：自动掷骰、放弃买地、结束回合——**绝不替你花钱** |
| 电脑玩家 | 由服务端自动走，大约每步 0.7 秒，感觉像一个人在慢慢想 |
| 掉线重连 | 直接刷新页面就会**自动回到原来的座位**；掉太久被电脑接手了，回来也会立刻交还 |
| 中途加入 | 房间里还有**纯电脑座位**时，新人可以顶替那台电脑直接开玩（见 4.3 和第五节同名问答） |
| 事件日志 | 点日志上的 `⤢ 展开` 可以全屏看历史，`Esc` 收起 |
| 掉线时 | 屏幕顶部会有提示横幅，告诉你正在自动重连 |
| 房主关掉服务端 | 所有人掉线，这局结束 |

**注意**：联机时每局由房主在房间里设时长（25 / 50 / 75 季度），房主也可以中途关掉服务端重开。

## 四、回合超时、掉线托管、中途加入

这三件事都是为了解决真机上遇到过的尴尬：**一个人掉线，整局卡死 40 分钟**。

### 4.1 回合超时

轮到你的时候屏幕上有倒计时，到点服务端替你执行**最保守的动作**：

| 阶段 | 超时 | 到点自动做什么 |
|---|---|---|
| 掷骰 / 买地 / 事件卡 / 监狱 | **90 秒** | 自动掷骰、放弃买地、接受卡片、继续蹲监狱 |
| 交易阶段（掷完骰子之后） | **180 秒** | 自动结束回合 |

原则是**绝不替你花钱**：不替你买地、不替你交保释金、不替你买股票或金融产品。
秒数是按真人实测定的：掷骰这些阶段真人 P99 才 59 秒，90 秒几乎不会误伤；
交易阶段真人中位就 54 秒、最长 207 秒，所以给到 180 秒。

### 4.2 掉线托管

* **只有在自己的回合、静默超过 60 秒**才会交给电脑。别人回合时你在发呆不会被误伤
  （那种时候你本来就不需要做任何动作）。
* **有挂起中的请求一定算在线**——长轮询最多挂 25 秒，如果只看"最后活跃时间"，
  网络健康的玩家撑过十几秒就会被误判掉线（这个坑踩过一次）。
* 玩家回来时**用房间号 + 原来的名字就能认回座位**，电脑立刻交还，日志里会写一句
  「👤 XX 回来了，重新接管自己的座位」。

### 4.3 中途加入（热加入）

* 房间已经开局，但还有**纯电脑座位**时，新人可以**中途顶替一台电脑**坐进去继续玩。
* **掉线玩家的座位不会被抢**——那个座位只留给本人回来认领，哪怕是电脑在替他打。
* 两种回归方式：
  1. **同一个浏览器直接刷新** → 自动认回（浏览器里存着身份）；
  2. **「联机对战」→ 输房间号 + 原来的名字** → 也能认回（房主重启过服务端时靠这条）。

## 五、常见问题

**Q：朋友打开是「无法访问此网站」**
A：按顺序排查 —— ① 是不是把 `127.0.0.1` 发给朋友了？那在他电脑上指的是他自己，要发 `192.168.x.x` 那个；② 两台机器是不是同一个 WiFi（手机热点也算）？③ 房主的 Windows 防火墙有没有放行 Node.js（专用网络）？④ 公司/学校网络常常禁止设备互访，换热点试试。

**Q：房间号输进去说「没有这个房间号」**
A：房间号是 4 位、字母大写。房主重启过服务端的话，旧房间号就失效了，要重新创建。房主最多同时开几十个房间，不影响。

**Q：刷新之后我变成了旁观者 / 座位没了**
A：正常情况刷新会自动回座位。如果清过浏览器数据（localStorage）导致身份丢了，
就用「联机对战」→ **输房间号 + 原来的名字**，照样能认回自己的座位；实在不行才等下一局。

**Q：能不能中途加入？**
A：看情况。房间里有**纯电脑座位**（创建时人数没填满，空位自动补的电脑）时，新人可以**顶替一台电脑**坐进去继续玩；
如果座位全是真人（包括掉线但还没被托管的），就只能等下一局。
**掉线玩家的座位不会被别人抢**，那是留给本人回来认领的。

**Q：某一回合有人一直不动，整局就卡住了？**
A：不会。① 轮到他之后**静默超过 60 秒**，服务端就把他的座位交给电脑，别人不用等；
② 就算没判定掉线，每个阶段也有硬超时（掷骰/买地/事件/监狱 **90 秒**、交易 **180 秒**），到点服务端替他走最保守的一步。
他本人回来（刷新页面，或重新输房间号 + 原来的名字）电脑立刻交还。

**Q：股票必须等轮到自己才能买吗？**
A：不需要。**任何人的回合都能买卖股票**——不用等轮到你才看行情。
只有两种情况例外：自己在坐牢，或者场上有人正弹着买地窗口做决定。

**Q：异地的时候卡不卡？**
A：状态包很小（每步约 30~60 KB 的完整快照），Tailscale 直连的情况下和局域网没区别；cloudflared 走 Cloudflare 边缘节点，国内可能会有几百毫秒延迟，能玩但走子动画会稍慢。

## 六、单文件版能联机吗？

**不能。** [`dist/地产股神.html`](../dist/地产股神.html) 是给「一台电脑、几个人轮流」的热座模式用的，
用 `file://` 直接打开时浏览器不允许它去连服务端。

想联机就必须走 `node server.mjs` 然后用 `http://` 打开页面。热座和联机两种模式都能加电脑玩家。

## 七、技术细节（想自己改的话看）

```
server.mjs           零依赖服务端：静态文件 + 房间管理 + AI 驱动 + 长轮询推送 + 超时/托管
src/net.js           客户端联机层：大厅、长轮询接收（含重试/认座）、操作上报
tools/test-net.mjs   联机集成测试（真起服务端跑完整个流程）
tools/snapshot.mjs   抓存档（断线救援用），产出 saves\ 下的 ASCII 名 JSON
tools/watch.mjs      只读旁观 + 录制一局，产出 logs\对局-<房间号>-<时间>.jsonl
```

* **服务端持有唯一的游戏状态**，客户端只做两件事：渲染收到的状态、把操作 POST 回去。
* 传输用 **长轮询收状态 + POST 发操作**，所以不需要 WebSocket，也不需要任何 npm 包。
  * 服务端有变化时挂起的请求**立刻返回**（本机实测端到端唤醒延迟 **19ms**），没变化就挂起 25 秒再回一个"没变化"，客户端马上再问。所以延迟和推送一样是即时的。
  * 公网实测：穿过隧道挂起 4 秒后触发开局，**1 秒内被唤醒**。
  * **早期版本用过 SSE，为什么换掉**：Cloudflare Quick Tunnel 会把 `text/event-stream` 缓冲住——实测本机回环首帧立刻到，走公网隧道 **20 秒 0 字节**。结果就是"房主已经开局了，其他人还在加载"。长轮询是一个普通的完整 HTTP 响应，任何隧道/代理都能过。这是换传输层的唯一原因。
  * 服务端仍保留 `GET /api/events`(SSE) 供局域网调试，但客户端默认不用它。
* **POST 超时重试 + 幂等**：公网隧道实测约 **8%** 的 POST 会丢，所以客户端加了 **8 秒超时 + 自动重试 3 次**；
  每个操作带一个**幂等请求编号**（`reqId`），重试复用同一个编号，服务端认得，**不会重复执行**——
  比如不会因为重试把同一块地买两次、扣两遍钱。
* **回合超时**（`T_ROLL=90` / `T_TRADE=180`，可用环境变量 `DGS_T_ROLL` / `DGS_T_TRADE` 覆盖）：
  服务端维护权威的 `deadline`（Unix 毫秒时间戳）随状态下发，客户端只负责读它画倒计时。
  到点由 `forceAdvance()` 走最保守分支——自动掷骰、放弃买地(`decline`)、`stayInJail()`、`endTurn()`，**不产生任何花钱的操作**。
* **掉线托管**（`GRACE=60000`，环境变量 `DGS_GRACE`）：看门狗每 500ms 扫一遍，只对"当前回合 + 静默超时"的座位
  把 `isAI` 置真，并标 `autoAI` 表示**可被本人认回**。判定前先看有没有挂起的长轮询 waiter / SSE 连接，
  有就续命——否则健康玩家会被误判掉线。
* **热加入**：`POST /api/join` 带 `hotjoin: true` 时，在已开局的房间里找一台**纯电脑**（`isAI` 且非 `autoAI`）坐下；
  被托管（`autoAI`）或真人的座位一律不给，只能由本人用 token 或"房间号 + 名字"认回。
* **炒股不绑回合**：`buyStock`/`sellStock` 不再要求 `phase === 'awaiting-trade'`、也不要求轮到自己，
  只保留两条例外——自己在坐牢（`jailTurns > 0`）、或场上有人正弹着买地窗口（`pending.type === 'buy'`）。
  升级/抵押/赎回/卖回银行/金融产品仍然要求交易阶段。
* 每次变化广播一份**完整状态快照**（4 人局早期约 12 KB、后期约 20 KB），日志只带最后 120 条（否则 500 条日志会让包涨到 45 KB）。
* 操作会校验：**必须轮到你、阶段要对、参数合法**，否则直接拒绝并回一句原因。
* 客户端身份是一个随机 token，存在浏览器 localStorage 里，所以刷新/掉线能回到原座位；
  token 失效（房主重启过服务端）时退回"房间号 + 原来的名字"认座。
* 想快速跑一局测试：`DGS_AI_DELAY=25 node server.mjs`（把电脑每步 0.7 秒压到 0.025 秒）。

